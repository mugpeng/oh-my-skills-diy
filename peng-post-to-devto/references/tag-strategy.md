# Dev.to Tag Strategy

Tags are the primary discovery mechanism on Dev.to. Choosing the right tags significantly impacts reach.

## Rules

- Maximum **4 tags** per article
- Tags must be **lowercase**, no spaces
- Max **30 characters** per tag
- First tag is primary (appears in URL path)

## Tag Selection Strategy

1. **One broad tag** for reach (e.g. `javascript`, `webdev`, `programming`)
2. **One niche tag** for targeted audience (e.g. `rust`, `devops`, `react`)
3. **One audience tag** if applicable (e.g. `beginners`, `career`)
4. **One topic tag** for the specific subject (e.g. `cli`, `testing`, `api`)

## What Performs on Dev.to

| Content type | Performance | Notes |
|--------------|-------------|-------|
| Beginner tutorials | High | Largest audience segment |
| Listicles ("10 tools...") | High | Easy to consume |
| Career advice | High | Aspirational content |
| Hot takes | Medium-high | Controversial drives engagement |
| Deep technical | Medium | Niche but engaged audience |
| Project showcases | Medium | Best with story behind it |
| News/updates | Low | Competes with official sources |

## Optimal Article Length

- **1000-2500 words** performs best
- Include code examples when relevant
- Use headings, lists, and images for scannability
